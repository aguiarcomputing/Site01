Segurança: verificar configurações de firewall, usuários, permissões, pacotes desatualizados, etc.

1. Verificar atualizações de segurança.

Pacotes desatualizados podem ser uma vulnerabilidade. Vamos checar se há atualizações disponíveis:
sudo apt update
sudo apt list --upgradable

Se houver pacotes listados, atualize-os com:
sudo apt upgrade -y

Para atualizações críticas de segurança, você pode usar:
sudo unattended-upgrades

2. Checar usuários e permissões
Vamos ver quem tem acesso ao servidor:

Liste todos os usuários:
cat /etc/passwd

Filtre usuários com shell válida (potenciais logins):
cat /etc/passwd | grep -E '/bin/bash|/bin/sh'

Verifique usuários com UID 0 (superusuários além do root):
awk -F: '$3 == 0 {print $1}' /etc/passwd

Se encontrar usuários suspeitos, investigue ou remova com:
sudo deluser nome_do_usuario

3. Analisar permissões de arquivos críticos
Arquivos como /etc/shadow e /etc/passwd devem ter permissões restritas:
ls -l /etc/passwd /etc/shadow

Esperado:
/etc/passwd: -rw-r--r-- (644)
/etc/shadow: -rw-r----- (640 ou 600)

Corrija se necessário:
sudo chmod 644 /etc/passwd
sudo chmod 640 /etc/shadow

4. Verificar o status do firewall
Confira se o UFW (ou outro firewall) está ativo:
sudo ufw status

Se estiver inativo, ative e configure regras básicas:
sudo ufw enable
sudo ufw allow 22/tcp  # Libera SSH (ajuste a porta se necessário)
sudo ufw allow 80/tcp  # Libera HTTP (se aplicável)
sudo ufw allow 443/tcp # Libera HTTPS (se aplicável)

Liste regras para revisar:
sudo ufw status numbered

5. Checar portas abertas
Veja quais serviços estão escutando na rede:
sudo netstat -tulnp | grep LISTEN

Ou, se preferir usar ss (mais moderno):
sudo ss -tuln

Identifique serviços desnecessários e desative-os, se for o caso, com:
sudo systemctl stop nome_do_servico
sudo systemctl disable nome_do_servico

6. Analisar tentativas de login
Verifique se há tentativas de login suspeitas:

Logs de autenticação:
sudo cat /var/log/auth.log | grep "Failed"

Filtre por tentativas de SSH, se aplicável:
sudo cat /var/log/auth.log | grep "sshd.*Failed"
sudo apt install fail2ban -y
sudo systemctl enable fail2ban
sudo systemctl start fail2ban

7. Verificar processos suspeitos
Liste processos em execução para identificar algo fora do comum:
ps aux | less

Procure por processos com nomes estranhos ou alto uso de recursos sem justificativa. Mate processos suspeitos com:
sudo kill -9 PID

8. Checar configurações do SSH
Se você usa SSH, garanta que ele esteja seguro:

Edite o arquivo de configuração:
sudo nano /etc/ssh/sshd_config

Sugestões:
Desative login como root: PermitRootLogin no
Use uma porta diferente de 22: Port 2222 (exemplo)
Restrinja usuários: AllowUsers usuario1 usuario2
Reinicie o SSH após alterações:
sudo systemctl restart sshd


=============== Desempenho: uso de CPU, memória, disco, processos em execução. ========================= 
1. Monitorar uso de CPU
Vamos checar como a CPU está sendo utilizada:

Use o comando top para uma visão em tempo real:
top

Veja a linha %Cpu(s):
us (usuário), sy (sistema), id (ocioso). Se id estiver baixo (ex.: <10%), a CPU está sobrecarregada.
Identifique processos com alto uso na lista (coluna %CPU).

Para uma alternativa mais leve, use htop (se instalado):
htop

Se não tiver, instale com: sudo apt install htop -y.
Liste os 5 processos que mais consomem CPU:
ps aux --sort=-%cpu | head -n 6

2. Verificar uso de memória
Cheque se a memória RAM está sendo um gargalo:

Use o comando free:
free -h

Veja a coluna used vs available. Se available estiver muito baixo (ex.: <10% do total), pode haver problemas.
Detalhes de uso por processo:
top
Ordene por memória pressionando Shift + M (coluna %MEM).
Ou liste os 5 processos que mais consomem RAM:
ps aux --sort=-%mem | head -n 6

Se houver swap excessivo (coluna Swap em free -h), pode indicar falta de RAM física.

3. Analisar uso de disco
Espaço em disco cheio ou I/O intenso podem afetar o desempenho:

Verifique espaço disponível:
df -h

Procure partições com uso próximo de 100%. Se necessário, limpe arquivos grandes:
sudo find / -type f -size +100M

Monitore I/O (leitura/escrita em disco):
iostat -x 1

Instale se necessário: sudo apt install iotop -y.

4. Checar processos em execução
Muitos processos ou serviços desnecessários podem consumir recursos:

Liste todos os serviços ativos:
systemctl list-units --type=service --state=running

Desative serviços não essenciais:

sudo systemctl stop nome_do_servico
sudo systemctl disable nome_do_servico

Veja o número total de processos:
ps -e | wc -l

Um número muito alto (ex.: centenas) pode indicar algo errado, dependendo do uso do servidor.

5. Monitorar rede
Problemas de desempenho podem vir de tráfego excessivo:

Veja o uso de banda:
ifstat
Instale se necessário: sudo apt install ifstat -y.
Liste conexões ativas:
netstat -tunap | grep ESTABLISHED

Ou com ss: ss -tunap | grep ESTAB.
Procure por conexões inesperadas ou em excesso.

6. Logs de desempenho
Analise logs para identificar problemas históricos:

Veja mensagens do sistema:
sudo journalctl -p 3 -xb

-p 3 mostra erros críticos; -xb desde o último boot.
Procure por "out of memory", "CPU throttle" ou falhas de disco.

Diagnóstico e ações
CPU alta: Mate ou otimize processos pesados (ex.: kill -9 PID).
Memória cheia: Adicione mais RAM ou ajuste serviços (ex.: limite uso do Apache/Nginx).
Disco cheio: Libere espaço ou expanda armazenamento.
I/O lento: Verifique hardware (ex.: SSD vs HDD) ou otimize aplicações.
