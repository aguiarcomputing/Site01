1. Atualizações e Manutenção Básica (Segurança: Patches Regulares)

Sempre comece atualizando o sistema para mitigar vulnerabilidades conhecidas.

apt update && apt full-upgrade -y
reboot

Ative atualizações automáticas de segurança (sem reboot automático para evitar downtime em produção):

apt install unattended-upgrades
dpkg-reconfigure unattended-upgrades  # Selecione "Yes" para atualizações de segurança

3. Segurança de Rede e Firewall

Firewall Proxmox: Ative globalmente no GUI (Datacenter > Firewall > Options > Enable: Yes). Crie regras:

Permita apenas portas essenciais: 22 (SSH), 8006 (GUI), 3128 (SPICE).
Para VM TrueNAS: Permita 80/443 (web), 111/2049 (NFS se usado).
CLI exemplo: pve-firewall enable --table in (entrada) e pve-firewall compile para testar.


Rede Segura: Use VLANs se possível (ex.: bridge vmbr0 para management, vmbr1 para VMs). Desabilite IPv6 se não usado: Edite /etc/default/grub com ipv6.disable=1 e update-grub.
Fail2Ban: Instale para bloquear brute-force: apt install fail2ban. Edite /etc/fail2ban/jail.local:

[sshd]
enabled = true
[proxmox]
enabled = true

Reinicie: systemctl restart fail2ban.

4. Autenticação e Acesso (Evite Root Direto)

SSH Seguro: Desabilite login root por senha. Gere chaves: ssh-keygen no cliente, copie com ssh-copy-id root@seu-ip.

filezilla sftp://192.168.150.158 salvar chaves.

Edite /etc/ssh/sshd_config: PermitRootLogin prohibit-password e PasswordAuthentication no. Reinicie: systemctl restart ssh.


Usuários Proxmox: Crie usuário não-root: No GUI (Datacenter > Permissions > Add > User), adicione "pveadmin" com realm PAM, senha forte. Atribua roles (ex.: PVEVMAdmin para VMs).

Crie Grupo Proxmox: Datacenter > Grupos > Criar

Dar Permissões para Grupo Proxmox: Datacenter > Grupos > Criar


Ative 2FA: GUI > User > [seu-user] > Two Factor > Enable TOTP (use app como Authy).


GUI Segura: Acesse só via HTTPS (padrão). Mude senha root no GUI se fraca.


Script para Implementar Regras de Firewall
Abaixo está um script para configurar regras de firewall no nível do datacenter e da VM TrueNAS. Ele assume que sua rede confiável é 192.168.150.0/24 e que o TrueNAS usa portas 80/443 (web) e 2049 (NFS, se aplicável). Ajuste IPs/portas conforme necessário.

ACRONIS

Passo 1: Preparação no Proxmox VE

Acesse o shell do Proxmox (via SSH ou console web: root@seu-host:~#).
Atualize o sistema:
Obs. Servidor Vai reiniciar com esse comando.

apt update && apt full-upgrade -y
reboot

Isso garante que o kernel (geralmente 6.8+ na VE 8.3.0) esteja pronto. Se houver problemas com headers do kernel (comum em instalações agent-based), instale:

apt install pve-headers-$(uname -r) build-essential gcc make perl

Se der algum erro segue esse procedimento.

Certifique-se de que /etc/apt/sources.list.d/pve-enterprise.list está comentado (com #) ou vazio, já que você não parece ter uma subscrição enterprise:
nano /etc/apt/sources.list.d/pve-enterprise.list
# Comente a linha: # deb https://enterprise.proxmox.com/debian/pve bookworm pve-enterprise

Adicione o repositório pve-no-subscription em /etc/apt/sources.list (ou em /etc/apt/sources.list.d/pve-no-subscription.list):

deb http://download.proxmox.com/debian/pve bookworm pve-no-subscription

Adicione o repositório pve-test para garantir acesso ao kernel 6.14 e seus headers (adicione em /etc/apt/sources.list.d/pve-test.list):
deb http://download.proxmox.com/debian/pve bookworm pve-test

apt update

Isso puxa os headers mais recentes da série 6.14 (incluindo 6.14.8-2-pve).
Alternativamente, instale o metapackage para todos os kernels suportados:

apt install proxmox-headers-6.14

Isso garante que headers sejam instalados automaticamente para qualquer kernel futuro que você usar.
Verifique se os headers foram instalados:
dpkg -l | grep proxmox-headers
ls /usr/src/proxmox-kernel-6.14.8-2-pve


Você deve ver arquivos de header (ex: Makefile, include/) no diretório /usr/src/proxmox-kernel-6.14.8-2-pve.

No shell do Proxmox, instale o agente:

Baixe o pacote (substitua pela URL do seu download da Acronis):
wget https://br01-cloud.acronis.com/download/u/baas/4.0/25.8.40800/CyberProtect_AgentForLinux_x86_64.bin  # Ou .deb se disponível

Para RPM (Proxmox é Debian-based, mas Acronis suporta via alien ou rpm):
dpkg -i agent.deb
apt install -f -y  # Corrige dependências

Versão de kernel incorreta:

Se o kernel 6.14.8-2-pve não for padrão no Proxmox VE 8.3.0, instale um kernel compatível:
apt install pve-kernel-6.8
reboot

O instalador deve reconhecer os headers agora. Se solicitado, insira suas credenciais da Acronis Cloud para registro.
Se você escolheu "Skip" anteriormente, verifique se o agente está funcionando:

systemctl status acronis_mms acronis_agent

Passo 3: Instale o Agente

Torne o instalador executável:
chmod +x CyberProtect_AgentForLinux_x86_64.bin  # Ajuste o nome do arquivo

Execute o instalador:
./CyberProtect_AgentForLinux_x86_64.bin

Instale o plugin Proxmox:
Durante a instalação, o agente detectará o Proxmox e instalará o add-on automaticamente. Se não, execute:
/opt/acronis/agent/bin/acronis_register  # Registre com sua conta Acronis

Forneça o token/ID da Acronis gerado no console web.

Reinicie o serviço:
systemctl restart acronis_agent
reboot  # Pode ser necessário para compilar módulos kernel
